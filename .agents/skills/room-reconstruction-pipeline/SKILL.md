# 室内重建与渲染流水线

复用已有证据和资产。先判断用户要照片分析、标注应用、模型同步、校验还是渲染；不要为了套全流程重做已经确认的房间，也不自动发布网页。

## 选择入口

- **只有照片**：先做编号/去重、稳定资产ID、逐图机位和左右/遮挡/同墙关系、承托链、尺寸/间距与颜色纹理观察。按同级的 [room-photo-inventory](../room-photo-inventory/SKILL.md) 整理证据。单独安装本 skill 时，可按 [输入契约](references/contracts.md) 记录证据与未知项。
- **有深度/GLB**：按 [扫描适配](references/scan.md) 检查格式、单位、轴和位姿。支持的关键帧格式可用 `scripts/fuse_depth.py`；融合不等于GLB配准、语义分割或完整物品量尺。
- **用户补了尺寸/间距**：保留原文，确认编辑已保存；生成带源哈希的规范化 review JSON，运行 `scripts/layout_constraints.py`。歧义、约值与缺项明确标记，不把自由文本直接执行成坐标。
- **从候选升级完整房间**：使用同级的 [room-inventory-to-blender](../room-inventory-to-blender/SKILL.md) 的完整外壳与中央相机约定；已有工程则增量升级。新墙门必须有证据或显式补全依据，不能从“凹位”推导出额外隔墙。
- **详细模板跟随布局**：读取 [模板与校验契约](references/blender.md)，检查原点、单位、真实前向，再配置 bindings。使用 `scripts/blender_pipeline.py sync` 另存新工程；不靠父级yaw相等判断椅背/屏幕方向。
- **核对/渲染已有模型**：直接使用同一脚本的 `qa` 或 `render`，无需重建。渲染取景和质量是配置值，先试小图，再出整体/局部；只重出受影响视图。

## 不再重复的错误

1. 事实、用户确认、可见扫描统计、建模估值分开。房间照片的左右不等于世界轴；未知深度不能填成完整尺寸。
2. 同类设备可能分别由地面和台面承托。先看完整底边及跨视角证据，再匹配实例。
3. 尺寸改变后重算同一参照面的净距。`gap` helper 明确只计算世界AABB面距，不冒充任意旋转表面最短距离。
4. 模板坐标适配只做一次。先检查实际椅背/坐面，再声明 source/layout forward；屏幕与外框使用共同局部变换，俯仰和吊杆分开。
5. 椅子数量/位置确认后，不删椅绕过冲突。座面可推入桌下，地面投影重叠不自动代表实体穿插。
6. 照片明暗不直接当底色或强Bump。先用样板渲染验证表面效果，再复用到全房；粗糙度和凹凸强度等无法实测的值应标为假设。

## 执行与交付

运行命令、配置格式见 [输入契约](references/contracts.md) 和 [Blender命令](references/blender.md)。复现示例可用 `scripts/create_test_room.py` 生成独立的模型、布局与配置，见 [合成示例与验证](references/examples.md)。处理实际房间时，按本次证据建立布局和对象映射。

同步另存 `.blend`，校验输出 JSON，渲染输出独立目录和来源指纹。保留当前版本截图、已应用/未绑定对象、未知和检查边界；不能把空检查或0个椅子写成通过。重新打开保存的工程执行校验。配置椅子朝向检查时，可用 `--negative-probe` 验证程序会拒绝反向网格。

用户要报告时按当前工程的报告要求交付，标明截图版本和检查范围。用户要漫游时，根据目标平台另做导出，分别验证网页颜色、碰撞和性能。

这些脚本提供数据校验、模板同步和渲染。物品观察、未知户型推断和全屋碰撞评估需按实际任务单独处理。
