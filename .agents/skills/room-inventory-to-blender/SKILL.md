# 图片与空间清单到完整 Blender 室内模型

目标是可以从内部看完整四周的房间，而非缺墙、去顶的展示沙盘。完整外壳和中央相机属于交付条件；未知户型保持假设标记。已有 .blend 时先检查并另存，不能为套模板清空用户场景。

## 输入与技能衔接

先定位图片、`images-manifest.json`、`objects.json`、`image-spatial-relations.json`、`furniture-distances.json`，以及可选的 `layout-candidate.json`、校验记录、既有 .blend。阅读 [输入与场景约定](references/input-and-scene-contract.md)。检查所有可用图片总览与关键原图，不只读物品名字。

- 输入缺少观察、去重或逐图关系时，使用 **room-photo-inventory** 补齐；已有可用清单直接消费，不反复分析。单大件图无物品间关系、缺图无观察关系。
- 建模阶段使用 **blender-director** 做简短制作规划，**archviz / blender-modeler** 处理米制结构和可编辑几何，**prop-artist** 处理家具；按实际需要读取 **materials、lighting、camera-cinematography、rendering**。
- 交付时使用 **qa-review** 对照截图与检查记录；有网页需求才衔接 **blender-web-walkthrough**，有格式导出需求才使用 **asset-optimization / export-pipeline**。不为普通静态室内无条件启动角色、绑定、动画、模拟或全套游戏管线。
- 技能不可用时按本 skill 的输入、完整外壳、中央相机和验收约定继续；明确缺失能力，不能宣称调用了未读取的技能。专业建模技能为可选辅助；本仓库包含的上游照片分析见同级 [room-photo-inventory](../room-photo-inventory/SKILL.md)。常见模型问题见 [纠错经验](references/project-lessons.md)。

## 把关系转成建模约束

区分三类数据：照片里直接观察的事实、跨视角推断、为完成模型选择的假设。保留原清单和稳定 asset_id；将尺寸取值、全局坐标、区域连接与假设写入独立 `scene-spec.json`，不回填成已观察事实。

图片的左/右/上/下属于各自相机，不能直接变成全局 X/Y/Z。先用同面墙、门窗、拱洞、床、显示面等共同锚点确定相机方向，再转换布局。照片无法约束的绝对朝向可自行定义，但不得把相对镜像也当作任意旋转。优先满足门窗拓扑、同墙顺序、承托与嵌套、观看视线和通道，再做材质细节。

“依赖关系”至少分为：承托（地面→柜→台面物）、连接（墙→洞口→框→玻璃/门）、包含（圆桌处于环座凹区）、邻接/同墙以及逐图构图。按建造依赖排序，逐图左右关系不能拿来做拓扑排序。C 形座台与中心桌的包围盒相交可能正常，应检查真实几何。

当证据相互冲突时记录冲突和选择理由；未拍到的墙/顶按最少必要结构补全，标 assumed；不擅自增加厨房、阳台或额外家具。无法确证的卫生间连接标 UNKNOWN，不因模型能走通就宣称真实布局已还原。

## 用距离数据设定大小与位置

读取 [距离驱动布局](references/distance-driven-layout.md)。同时消费家具尺寸 ranges 与家具间距离区间：先确定尺度、选尺寸，再以距离与相对方向约束计算摆放位置。不能仍按固定坐标摆放后仅附加间距说明。每个尺寸选值保留源资产/维度；每条间距保留 source_distance_id、参照部位、目标值和最终实际值。沿同轴摆放时“中心距 = 两件半尺寸之和 + 边缘净距”，尺寸变更后重算位置，旋转/凹形资产按真实轮廓处理。

scene-spec 指向原始 inventory_file 和 distance_estimates_file，配置 dimension_constraints、distance_constraints。有尺度的数值记录必须实际应用或显式记 unresolved；unknown 不强填数值。证据相冲突时记录取舍，不改源范围来迎合已有模型；低置信度估算作为软约束，现场测量优先。保留完整外壳和中央相机的既有要求，间距冲突不可通过缺墙或移动中央机位悄悄绕过。

最终从同一参照部位回测模型，校验区间、偏差与未解决项。随附 validator 已支持配置的对象局部轴尺寸和距离 anchor 校验；指定点间距通过不代表真实表面最小净空或现场距离准确。旧清单无距离字段时标为未分析，触发上游补做；无可用证据时保留 UNKNOWN 和建模假设。

## 完整盒状室内与中央相机

1. **外壳完整**：矩形主房是四周实体墙、地板和顶板；异形/多房间沿真实候选轮廓闭合，不强塞成一个矩形。每个房间有完整顶面与地面，相邻区连通处有门洞。内墙、外墙、地面、天花独立可编辑，有合理厚度、角部搭接、正确法线；不能仅靠双面材质伪装无厚度模型。
2. **开口真实**：门窗、拱口、通透圆洞用真实几何开口；有墙厚的洞口带侧壁。窗框、窗帘或纹理不能遮住未切开的实墙冒充窗洞。外窗配实际玻璃、入户门默认闭合，保持外壳边界；内部通道保持可通行。已证实敞开的外部开口作为显式例外记录，不偷偷封死。圆洞/窗不当作门。完整空间不要求不同构件焊成单一水密网格。
3. **中央相机**：设 `CAM_Center` 为默认活动相机。其 X/Y 为主房净空边界中心，Z 默认地面 + 1.6 m，是人眼高度而非盒子高度的一半；如用户明确要求三维几何中心则使用该中心并记录。若中心被家具占用，保留中心约束并报告冲突，优先在证据允许范围内调整假设布局；不能偷偷把中央相机移到角落。另设入口观察相机并不替代中央相机。
4. **四向与对照**：从中央相机同一位置生成四向视图，只转朝向。拍照匹配使用独立 `CAM_Ref_<image_id>`，先近似匹配相机再修改物体；未标定时投影一致只能证明方向相容。中央相机须位于净空内、不在墙/家具/灯具中；近平面约 0.03–0.05 m，焦距从 24–28 mm 起调，不为塞进全部物件无限拉广角。
5. **禁止带剖切状态交付**：主场景和默认 View Layer 中，墙地顶以及外部关闭件的 `hide_render`、`hide_viewport`、`hide_set` 与 collection/exclude 状态均可见，camera ray visibility 正常。俯视/剖切使用独立场景或独立展示 View Layer；临时隐藏须 `try/finally` 恢复，最后重新打开保存文件验收，活动相机仍为中央相机。

新矩形工程可用 `scripts/create_room_shell.py` 和 `assets/scene-spec.example.json` 创建六面外壳、中央相机和同点四向相机。它只生成空壳基线，**不负责**按照片放家具、开窗门或恢复已有项目；改完配置后在独立后台进程运行，不对既有 .blend 套建壳。多房间/异形项目自行按相同约定构建。

## 建模与材质次序

先结构、开口、主要家具体块，核对尺度、左右顺序、通道与中央机位；再细化床品、座台、柜门、卫浴、窗帘褶皱。家具父级/自定义属性保留 asset_id，复合物体按资产计数，别按零件数量计数。生成代码从显式配置读取参数，不用截断另一脚本字符串来复用函数，不带历史绝对路径。

常用建模假设为层高 2.6–2.9 m、墙厚 0.12–0.20 m；这是可调整取值，不是实测或法规。门洞净宽、家电尺寸、床侧净空按当前清单确认。布局通道沿用下游方块玩家时默认宽深 0.44 m、高 1.7 m；校验应膨胀障碍并处理转角，不能用点通过或圆形行人校验冒充方块玩家通过。台阶与坡度单独记录，不声称平层寻路支持完整物理。

材质参考日光下近似本色，彩灯不烘进材质基础色；灯带用独立发光材质，布纹/木纹按真实尺度，避免墙面强凹凸、玻璃变实墙。照明应在封闭外壳下成立，不通过删墙删顶提亮。参考图、纹理、必要节点资源打包，源信息/假设/构建版本嵌入 Blender Text。

## 验收与交付

按 [验收约定](references/acceptance.md) 执行。随 skill 的 `scripts/validate_scene.py` 只读检查单位、外壳可见性、配置资产映射、中央相机、空间采样射线以及已绑定的源尺寸/间距，输出 JSON；不能把它的通过当作几何水密、照片匹配或路径可达认证。补充实际洞口射线、家具支撑/相交与身体净空检查，未做写 UNKNOWN。

交付 `room.blend`、配置 `scene-spec.json`、照片与资产映射、中央四向 PNG、`validation.json`、可复现构建脚本，及说明假设/限制的可编辑 HTML 报告。检查 .blend 重新打开后默认墙顶完整、相机仍在中心、资源无缺失。可选俯视图标明“剖切展示”，与主工程一致但不改变主工程默认状态。后续导出网页时另行映射 Blender Z-up 到 Web Y-up，不提前混用坐标；本 skill 不默认发布网页或覆盖已有漫游。
